# 仕様書: 閲覧履歴

本書は閲覧履歴の記録内容、参照方法、検索、再出力、保持と削除の仕様を定義する。

---

## 1. 記録対象

### 1.1 記録するイベント

| イベント | 記録内容 |
|---|---|
| `search` | 検索語、プロバイダ、結果件数、実行日時 |
| `next` | 追加取得したページ番号、追加件数 |
| `refine` | 変更前後の検索語 |
| `fetch` | 取得した URL、文書識別子、取得成功/失敗、所要時間、変換警告 |
| `outline` | 文書識別子、表示深度、見出し数 |
| `read` | 文書識別子、節識別子、見出しテキスト、出力文字数、切り詰めの有無 |
| `select` | 選択した検索結果・節、選択順 |
| `history` | 履歴参照操作（`list` / `show` / `grep` / `export`） |
| `delete` | 削除対象の種別と識別子、削除件数 |

### 1.2 記録しない情報

API キー、認証ヘッダ、Cookie、URL のクエリに含まれる秘匿パラメータ（`token`, `key`, `sig`, `password` 等を含む名前のパラメータ値）、本文全文。本文は文書キャッシュ側にのみ保存する。

### 1.3 記録の単位

1 操作 1 レコードとして追記する。レコードは次の必須フィールドを持つ。

| フィールド | 内容 |
|---|---|
| `id` | 履歴レコード識別子（`H1`, `H2`, … をセッションをまたいで連番。保存ファイル内で一意） |
| `at` | 実行日時（ISO 8601、UTC） |
| `session` | セッション識別子 |
| `type` | イベント種別 |
| `payload` | イベント固有の内容 |

---

## 2. 履歴の表示

### 2.1 一覧

既定では直近 20 件を新しい順に表示する。1 行 1 件とし、日時・種別・要約（検索語、URL、または節見出し）を表示する。件数は `--limit` で変更できる（最大 200）。

```text
H42  2026-11-07 14:25  read     D1:S3  2. 適応計画の策定  (3,560 字)
H41  2026-11-07 14:24  outline  D1     見出し 12 件 (depth=3)
H40  2026-11-07 14:23  fetch    D1     https://example.jp/adaptation
H39  2026-11-07 14:22  search   気候変動 適応策  duckduckgo  7 件
```

### 2.2 詳細表示

履歴識別子を指定すると、1 レコードの全フィールドを表示する。`read` の場合は節本文を再出力できる。キャッシュが有効であれば外部取得を行わない。

### 2.3 検索

キーワード、種別、日付範囲（`--before`, `--after`）、セッション識別子で絞り込める。検索対象は検索語・タイトル・URL・見出しテキスト・サイト名であり、本文全文は対象外とする。

### 2.4 セッション単位の表示

セッション識別子を指定した場合、そのセッションのイベントのみを時系列で表示する。対話モードの「履歴を見る」も同じ表示を用いる。

---

## 3. 再出力

### 3.1 節の再出力

履歴の `read` レコードから、同じ文書・節を再出力できる。出力には元の操作日時と、再出力であることを示す注記を付す。文書キャッシュが失効している場合は再取得を試み、失敗した場合は `E2001` を返して理由を表示する。

### 3.2 検索の再実行

履歴の `search` レコードから同じ検索語・プロバイダで再検索できる。新規セッションとして実行するか、既存セッションを継続するかを選択できる。

### 3.3 エクスポート

履歴を Markdown または JSON Lines 形式で標準出力またはファイルへ出力できる。Markdown 出力は、セッションごとに見出しを付け、`search` / `fetch` / `read` を時系列に並べる。本文は含めず、節見出しのみを含める（`--with-body` 指定時のみ本文を含める）。

---

## 4. 保持と削除

### 4.1 保持期間

既定は 90 日。`history.retention_days` で変更できる。0 は無期限を意味する。

### 4.2 上限

既定は 50,000 レコード。超過した場合は古いレコードから削除する。

### 4.3 削除

履歴の全削除は、確認を求めたうえで行う。非対話モードでは `--yes` を必須とする。削除は履歴ファイルの置き換えにより行い、削除後の復元はできない旨を表示する。

### 4.4 記録の整合性

履歴は追記専用とし、既存レコードの内容を書き換えない。削除はレコード単位の物理削除またはファイル全体の置き換えのみとする。破損行が含まれる場合は、その行をスキップして読み込みを継続し、件数を警告として表示する。
