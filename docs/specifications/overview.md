# 仕様書: 概要（Overview）

本書は `llmsearch` の目的・設計原則・用語・利用シナリオ・スコープを定義する。

---

## 1. 目的と背景

### 1.1 解決したい課題

LLM エージェントに Web 調査をさせると、検索結果ページの HTML や記事全文をそのままコンテキストへ流し込みがちである。これはコンテキストを浪費するだけでなく、ナビゲーションや広告などのノイズ、無関係な記述を大量に混入させ、回答品質を下げる原因になる。

人間は Web 調査の際に段階的な絞り込みを行っている。まず検索結果の一覧（タイトルと概要）を眺め、気になる数件を開き、記事の見出し構成だけを確認し、必要な節だけを読む。本ツールはこの手順をターミナル上に再現し、各段階で「次に何をするか」を利用者（人間または LLM）が選べるようにする。

### 1.2 提供する価値

- **段階的開示**: 一覧（既定 7 件）→ 見出し（既定 h1〜h3）→ 節本文の 3 段階だけをコンテキストへ出力する。
- **人間と同じ操作感**: 番号選択による対話メニューを提供する。検索結果では「終了 / 結果の選択 / 8 件目以降 / 検索語の修正」を選べる。
- **再現性**: 取得した文書の Markdown と閲覧履歴をローカルに保存し、後から同じ節を引き直せる。
- **エージェント親和性**: 対話メニューと同じ操作を非対話サブコマンドと構造化 JSON 出力でも提供する。

### 1.3 想定利用者

| 利用者 | 利用形態 | 重視する点 |
|---|---|---|
| LLM エージェント | ツール呼び出しとして 1 操作ずつ実行 | 出力の小ささ、JSON の安定性、失敗時の回復手段 |
| 開発者・研究者 | ターミナルで対話的に実行 | 操作の分かりやすさ、履歴の参照、検索語の試行錯誤 |
| 自動化スクリプト | 非対話サブコマンドの連結 | 終了コード、決定論的な出力 |

## 2. 設計原則

### 2.1 段階的開示（Progressive Disclosure）

各段階の出力は、次の判断に必要な最小限の情報に限定する。検索段階では本文を出さず、アウトライン段階では節本文を出さない。

### 2.2 コンテキスト予算の明示

出力の文字数を常に measure して表示し、上限を超える場合は切り詰めたうえで「切り詰めた」ことを明示する。暗黙の大量出力を行わない。

### 2.3 探索と取得の分離

検索（一覧の取得）と文書取得（HTML の取得と変換）は別操作とする。検索結果を選ばない限り、外部へ追加のリクエストを送らない。

### 2.4 決定論的な出力

同一の入力（同じクエリ・同じキャッシュ済み文書）に対しては、同一の出力を返す。並び順・番号・見出しの抽出規則は固定であり、実行のたびに変化しない。

### 2.5 ローカル完結とプライバシー

履歴・キャッシュ・設定はローカルディスクのみに保存する。テレメトリや外部への利用状況送信は行わない。API キーは履歴へ記録しない。

### 2.6 礼儀正しいアクセス

公開 Web へのアクセスは、robots.txt の尊重、ホスト単位のレート制限、識別可能な User-Agent の付与を既定動作とする。

## 3. 用語

| 用語 | 定義 |
|---|---|
| セッション | 1 回の起動から終了まで、または `--session` で継続される一連の操作単位。識別子は `YYYYMMDD-HHmmss-xxxx` 形式 |
| 検索結果 | 検索プロバイダが返した 1 件の結果。セッション内で `R1`, `R2`, … の識別子を持つ |
| ページ | 検索結果の集合のうち、一度に表示する区切り。既定は 7 件 |
| 文書 | 取得して Markdown 化した 1 つの Web ページ。セッション内で `D1`, `D2`, … の識別子を持つ |
| 見出し | Markdown 化された文書中の `#`〜`######` の行。レベルと本文テキストを持つ |
| アウトライン | 文書の見出しの一覧。既定では h1〜h3 のみを表示する |
| 節 | ある見出しから、同レベル以下の次の見出しの直前までの本文範囲 |
| スニペット | 検索結果に付随する短い概要文。既定 120 文字で切り詰める |
| コンテキスト予算 | 1 回の出力に含める最大文字数 |
| プロバイダ | 検索結果を供給する外部サービス（DuckDuckGo、SearXNG、Brave など） |
| 状態ディレクトリ | 設定・履歴・キャッシュを保存するローカルのディレクトリ |
| 対話モード | 番号入力のメニューで操作する起動モード |
| 非対話モード | 引数で 1 操作を実行して終了するモード |

## 4. 利用シナリオ

### 4.1 対話モードでの調査

利用者は `llmsearch` を引数なしで起動し、検索語を入力する。7 件の結果（番号・タイトル・URL・スニペット）が表示され、メニューから「2. 検索結果の選択」を選ぶ。選択した記事の見出し構成（h1〜h3）だけが表示され、読む節を選ぶとその節の Markdown だけが出力される。調査を終えると履歴に一連の操作が残る。

### 4.2 エージェントからの 1 回呼び出し

エージェントは検索、アウトライン取得、節読み取りをそれぞれ独立したコマンドとして実行し、JSON 出力を解釈して次の操作を決める。状態はセッション識別子を通じてプロセスをまたいで引き継がれる。

### 4.3 過去の閲覧の再参照

利用者は履歴を一覧表示し、過去に読んだ節を同じ識別子で再出力できる。キャッシュが有効な間は外部へ再取得を行わない。

## 5. スコープと非目標

### 5.1 初期リリースのスコープ

1. 3 種類の検索プロバイダ（DuckDuckGo、SearXNG、Brave）と、プロバイダの切り替え
2. 検索結果のページング（8 件目以降の表示）と検索語の修正
3. HTML の取得、本文抽出、Markdown 変換（見出し・リンク・リスト・表・コードブロックを保持）
4. 見出しアウトラインの表示（深さ既定 3、2〜4 に変更可能）
5. 節単位の抽出とコンテキスト予算に基づく切り詰め
6. 履歴の記録・一覧・検索・再出力・削除
7. 対話モードと非対話モード、テキスト出力と JSON 出力
8. 設定ファイル・環境変数・コマンドライン引数による構成

### 5.2 非目標

- ページ内容の要約・回答生成（本ツールは素材の提供に限定する）
- JavaScript 実行を伴うページの完全な描画（初期リリースでは検出して警告する）
- サイト内の複数ページ巡回、サイトマップ探索、クローリング
- 認証・Cookie・ペイウォールを伴うページの取得
- 検索エンジンのスクレイピングを目的とした大量・並列リクエスト
- 複数利用者での共有、サーバー常駐、リモート API としての提供

### 5.3 将来拡張の候補

ヘッドレスブラウザによる描画、MCP サーバーとしての提供、節の要約、複数文書の横断比較、PDF の取り込み。いずれも初期リリースの仕様には含めない。

## 6. 全体アーキテクチャ

### 6.1 パイプライン

1. 検索語を受け取り、プロバイダへ問い合わせる
2. 検索結果を正規化し、`R1` 以降の識別子を付与して一覧表示する
3. 利用者の選択に応じて、追加ページの取得・検索語の修正・終了のいずれかへ分岐する
4. 選択された結果の HTML を取得し、本文抽出を経て Markdown へ変換して文書として保存する
5. Markdown から見出しを抽出し、アウトラインを表示する
6. 選択された節の本文だけをコンテキスト予算の範囲で出力する
7. すべての操作を履歴へ追記する

### 6.2 状態の保持単位

セッション（クエリ・結果一覧・文書・選択状態）、文書キャッシュ（URL と Markdown の対応）、履歴（操作の時系列）の 3 つを状態ディレクトリに保持する。状態はプロセス終了後も再利用できる。

### 6.3 拡張点

1. **プロバイダ追加**: 検索結果の正規化形式を共通化し、プロバイダの追加が既存動作に影響しない構造とする。
2. **変換器の差し替え**: 本文抽出と Markdown 変換を独立した工程とし、変換方式を切り替えられるようにする。
3. **出力形式の追加**: テキストと JSON の出力形式を対等に扱い、将来の形式追加を容易にする。
4. **未知設定の温存**: 設定ファイルの未知キーを保持し、後方互換性を損なわない。
