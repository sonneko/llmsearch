# 仕様書: セッションと状態管理

本書はセッション識別子、状態ディレクトリの構成、保存単位、復元・破損時の扱いを定義する。

---

## 1. セッション識別子

### 1.1 形式

セッション識別子は `YYYYMMDD-HHmmss-xxxx`（`xxxx` は 4 桁のランダム英数字）とする。例: `20261107-142233-a7f3`。

### 1.2 生成と継続

対話モードの起動時、または `search` を `--session` なしで実行した際に新規セッションを作成する。`--session` で既存 ID を指定した場合はそのセッションを継続し、存在しない場合は新規作成する（作成した旨を標準エラーへ表示する）。

### 1.3 表示

対話モードでは起動時にセッション識別子を 1 行表示し、他のプロセスから継続できることを案内する。`--quiet` 指定時は表示しない。

### 1.4 有効期間

セッションは明示的に削除されるか、保持期間（既定 7 日、`session.ttl`）を過ぎるまで保持する。保持期間を過ぎたセッションは、一覧・継続の対象外とし、履歴からは参照できる。（履歴は別途保持期間を持つ。）

---

## 2. 状態の単位

### 2.1 セッション状態

1 セッションが保持する情報は次のとおり。

| 項目 | 内容 |
|---|---|
| `sessionId` | セッション識別子 |
| `createdAt` / `updatedAt` | 作成・更新日時（ISO 8601、タイムゾーンは UTC） |
| `queries` | 検索語の履歴（出現順）。各要素に検索語・プロバイダ・実行日時・結果件数 |
| `activeQuery` | 現在注目している検索。結果一覧のスロットを指す |
| `results` | 検索結果の一覧（識別子・順位・タイトル・URL・スニペット・サイト・公開日・由来クエリ） |
| `page` | 現在のページ番号、取得済みの最大ページ、プロバイダ上限到達フラグ |
| `documents` | 取得済み文書の参照（`D` 識別子、URL、文書 ID、取得日時、警告） |
| `outlineDepth` | 現在のアウトライン深度（既定 3） |
| `selections` | 選択済みの節（文書識別子、節識別子、選択順） |
| `pendingSelections` | 選択されたが未取得の検索結果 |

### 2.2 文書キャッシュ

文書は URL をキーとして保存する。1 文書に含める情報は本文 Markdown、メタデータ、取得日時、有効期限、変換方式、警告一覧、見出し索引（識別子・レベル・テキスト・開始行・終了行・文字数）である。

### 2.3 履歴

履歴はセッションをまたぐ操作ログであり、セッションが削除されても保持される。件数・容量の上限に達した場合は古いものから削除する。

## 3. 保存先

### 3.1 探索順

状態ディレクトリは次の順に決定する。

1. `--state-dir`
2. 環境変数 `LLMSEARCH_STATE_DIR`
3. 設定ファイルの `state.dir`
4. 既定値 `$XDG_STATE_HOME/llmsearch`、未設定時は `~/.local/state/llmsearch`

### 3.2 ディレクトリ構成

```text
<state-dir>/
├── config/              # 設定一式（settings.json, engines/, network/, filters/, quotas/）
├── sessions/
│   └── <sessionId>.json # セッション状態
├── documents/
│   └── <hash>/          # URL のハッシュによるディレクトリ
│       ├── meta.json    # メタデータ・見出し索引
│       └── body.md      # Markdown 本文
├── history/
│   └── history.jsonl    # 追記専用の操作ログ
└── cache/
    └── robots.json      # robots.txt の判定キャッシュ
```

### 3.3 権限

状態ディレクトリは所有者のみが読み書きできる権限（`0700`）で作成する。設定に API キーが含まれる場合があるため、ファイルは `0600` とする。

### 3.4 原子的な書き込み

状態の更新は一時ファイルへの書き込みとリネームにより行い、書き込み途中の状態が読まれないようにする。複数プロセスが同時に同一セッションを更新した場合は、後勝ちとし、衝突を検出したら `E5003` を返して再実行を促す。

---

## 4. 復元と破損時の扱い

### 4.1 復元

`--session` による再開時は、結果一覧・ページ・文書参照・選択状態を復元し、直近のアウトラインを再表示できる。キャッシュが失効している文書は「未取得」として扱い、取得操作を求める。

### 4.2 破損

セッション JSON の解析に失敗した場合、破損ファイルを `.corrupt-<timestamp>` に退避し、新規セッションとして継続する。この際 `W5001` を表示し、復旧できなかった項目を列挙する。履歴は破損したセッションの情報を参照しない。

### 4.3 不整合

`results` に含まれる文書参照がキャッシュに存在しない場合は、参照を無効として扱い、再取得を案内する。識別子の連番に欠番があっても、既存の識別子は変更しない。

### 4.4 容量管理

状態ディレクトリの合計サイズが既定 512 MiB を超えた場合、キャッシュ（文書）を古い順に削除する。セッションと履歴は容量削除の対象外とする。削除を行った場合は警告を表示する。

---

## 5. 削除

### 5.1 セッションの削除

`session.cleanup` 相当の操作（履歴の `clear` とは別）で、保持期間を過ぎたセッションを削除する。削除前に件数と合計サイズを表示し、確認を求める。非対話モードでは `--yes` を必須とする。

### 5.2 文書キャッシュの削除

履歴の特定エントリを削除した場合、そのエントリのみが参照する文書キャッシュは削除対象とする。他のセッションが参照している文書は削除しない。

### 5.3 秘匿情報

削除操作の結果は履歴に記録する（削除対象の識別子と件数のみ。本文は記録しない）。
