# 仕様書: エンジン定義（JSON）

本書は検索エンジンを JSON で宣言するための仕様を定義する。実装はエンジン固有の形式に依存せず、本書の宣言を評価するだけとする。

---

## 1. 基本方針

### 1.1 宣言と評価の分離

- エンジン 1 つは 1 つの JSON オブジェクト（ファイル）で表す。
- コアは「リクエスト定義に従って要求を組み立てる」「抽出ルールに従って応答を読む」ことのみを行う。
- エンジン名・ドメイン・HTML 構造に依存する処理をコードへ埋め込まない。組み込みの既定エンジンも JSON として同梱する。

### 1.2 対象とする応答

| `response.kind` | 対象 | 抽出方式 |
|---|---|---|
| `html` | HTML・XHTML | CSS セレクタ |
| `json` | JSON 文書 | ドット記法のパス（`[]` で配列展開） |

上記以外の応答（XML の名前空間付き RSS 等）は、初期リリースでは扱わない。RSS 形式の応答は検索エンジンの API で一般的であるため、`json` と同様に扱えるよう将来 `xml` を追加できる構造とするが、初期リリースのスコープ外とする。

### 1.3 定義の同一性とキャッシュ

エンジン定義の内容ハッシュを `engineHash` として記録する。同一クエリで同じ `engineHash` の結果はキャッシュを再利用できる（キャッシュの有効条件は設定の節で定める）。

---

## 2. エンジン定義の構造

### 2.1 トップレベル

| キー | 必須 | 型 | 内容 |
|---|---|---|---|
| `schemaVersion` | 必須 | 整数 | 定義スキーマの版。初期リリースは `1` |
| `id` | 必須 | 文字列 | エンジンの識別子。`[a-z0-9][a-z0-9._-]*` |
| `name` | 任意 | 文字列 | 表示名。省略時は `id` |
| `description` | 任意 | 文字列 | 説明。`engines list` に表示する |
| `enabled` | 任意 | 真偽値 | 既定 `true`。`false` のとき選択候補に含めない |
| `tags` | 任意 | 文字列配列 | 用途タグ（`general`, `news`, `academic` 等）。一覧の絞り込みに使う |
| `network` | 任意 | 文字列 | ネットワークプロファイル ID。省略時は既定プロファイル |
| `request` | 必須 | オブジェクト | リクエスト定義（§3） |
| `response` | 必須 | オブジェクト | 応答と抽出の定義（§4） |
| `paging` | 任意 | オブジェクト | ページング定義（§5） |
| `limits` | 任意 | オブジェクト | エンジン固有の上限（§6） |
| `defaults` | 任意 | オブジェクト | 結果に付す既定値（言語・地域等） |

### 2.2 未知キーの扱い

定義に未知のキーが含まれる場合、検証は警告 `W1002` を出して継続し、キーを温存する。将来のスキーマ拡張時に既存定義を書き換えずに済ませるためである。

---

## 3. リクエスト定義（`request`）

### 3.1 構造

| キー | 必須 | 型 | 内容 |
|---|---|---|---|
| `method` | 任意 | 文字列 | `GET`（既定）または `POST` |
| `url` | 必須 | 文字列 | エンドポイント。テンプレート変数を含められる |
| `query` | 任意 | オブジェクト | クエリパラメータ（値はテンプレート） |
| `headers` | 任意 | オブジェクト | 追加ヘッダ（値はテンプレートまたは `value_env` 参照） |
| `body` | 任意 | 文字列 | `POST` 時の本文（`contentType` と併用） |
| `contentType` | 任意 | 文字列 | 本文の Content-Type。既定 `application/x-www-form-urlencoded` |
| `encoding` | 任意 | 文字列 | クエリの文字符号化。`utf-8`（既定）または `euc-jp`, `shift_jis`, `gbk` 等 |
| `timeoutMs` | 任意 | 整数 | このエンジン固有のタイムアウト。省略時はネットワークプロファイルの値 |

### 3.2 テンプレート変数

文字列中で `{{name}}` 形式の変数を展開する。値は展開時に URL エンコード（`encoding` に従う）する。二重エンコードを避けるため、展開は 1 回のみ行う。

| 変数 | 内容 |
|---|---|
| `query` | 正規化済みの検索語 |
| `queryRaw` | 入力そのままの検索語（エンコードのみ） |
| `offset` | 結果の開始位置（0 始まり）。`paging.offsetParam` と併用 |
| `page` | ページ番号（1 始まり） |
| `limit` | 1 ページの件数 |
| `locale` | `defaults.locale` の値 |
| `region` | `defaults.region` の値 |
| `apiKey` | 認証情報の値（`value_env` で解決済み）。ヘッダ・クエリの双方で使用可 |
| `dateFrom` / `dateTo` | 日付指定（`YYYY-MM-DD`）。未指定時は空文字 |

### 3.3 認証情報の参照

認証情報は値を直接記述せず、次のいずれかで間接参照する。

- `{"value_env": "SEARXNG_TOKEN"}` : 環境変数の値を展開する。
- `{"value": "fixed"}` : 固定値。API キー以外の用途に限定する。

`value_env` が指す環境変数が未設定の場合、そのエンジンは「利用不可」と判定し、選択時に `E4002` を返す。値そのものはログ・履歴・`engines list` に表示しない。

### 3.4 送信前の検証

次の場合は送信せずに `E1004`（定義の不備）を返す。URL が `http` / `https` 以外、テンプレート変数が未知、`{{apiKey}}` を使用しているのに `value_env` が無い。

## 4. 応答と抽出（`response`）

### 4.1 構造

| キー | 必須 | 型 | 内容 |
|---|---|---|---|
| `kind` | 必須 | 文字列 | `html` または `json` |
| `charset` | 任意 | 文字列 | 応答の文字符号化。省略時は自動判定 |
| `items` | 必須 | オブジェクト | 1 件の結果を表す範囲の指定 |
| `fields` | 必須 | オブジェクト | 各フィールドの抽出ルール |
| `errorWhen` | 任意 | 配列 | 「結果なし」とみなす条件（§4.5） |

### 4.2 `items` の指定

- `html` の場合は `{"selector": "..."}` で結果 1 件ごとの要素を指定する。
- `json` の場合は `{"path": "..."}` で結果配列の位置を指定する。

### 4.3 `fields` の指定

`title`, `url`, `snippet`, `site`, `published`, `date` の 6 種類を扱う。`title` と `url` は必須、他は任意である。

各フィールドは次のいずれかの形式で記述する。

| 形式 | 意味 |
|---|---|
| `{"selector": "h2 > a", "attr": "href"}` | `items` 配下の要素から CSS セレクタで取得する。`attr` 省略時はテキスト |
| `{"path": "title"}` | `items` 配下のオブジェクトからドット記法で取得する |
| `{"from": "url", "transform": ["absolutize"]}` | 他のフィールドを元に変換する |
| `{"const": "duckduckgo"}` | 固定値 |
| `{"join": ["title", "snippet"], "separator": " "}` | 複数フィールドの結合 |

### 4.4 変換（`transform`）

変換は配列で指定し、先頭から順に適用する。

| 変換 | 内容 |
|---|---|
| `trim` | 前後の空白（全角空白を含む）を除去する |
| `collapse_ws` | 連続する空白・改行を 1 つの半角空白にする |
| `strip_html` | 含まれるタグを除去する |
| `decode_entities` | HTML エンティティを復号する |
| `absolutize` | 相対 URL を `request.url` を基準に絶対化する |
| `unwrap_redirect` | リダイレクト用 URL のクエリから実 URL を抽出する。`keys` で参照キーを指定できる |
| `strip_tracking` | 追跡パラメータを除去する（一覧は設定で変更できる） |
| `truncate` | 指定文字数で切り詰める（`chars` を併記） |
| `replace` | 正規表現置換（`pattern`, `with`） |
| `lower` / `upper` | 大小文字変換 |
| `to_date` | 日付文字列を `YYYY-MM-DD` に正規化する（`formats` を指定できる） |

### 4.5 結果なしの判定（`errorWhen`）

配列で条件を指定する。該当した場合は「結果 0 件」として扱う（エラーにしない）。

| 条件 | 内容 |
|---|---|
| `{"field": "title", "empty": true}` | タイトルが空である |
| `{"contains": "利用制限"}` | 応答本文に特定の文字列が含まれる |
| `{"path": "error", "exists": true}` | JSON に特定のパスが存在する |
| `{"status": 429}` | ステータスコードが一致する |

### 4.6 抽出できなかった場合

`title` または `url` が空の結果は破棄する。全件が破棄された場合、応答の保存内容（先頭 2048 文字のテキスト）を `W4004` とともに表示する。応答本文をそのまま出力することはしない。

## 5. ページング定義（`paging`）

### 5.1 構造

| キー | 型 | 内容 |
|---|---|---|
| `style` | 文字列 | `offset`（既定）または `page` |
| `offsetParam` | 文字列 | `style=offset` のとき、開始位置を渡すクエリ名（既定 `s`） |
| `pageParam` | 文字列 | `style=page` のとき、ページ番号を渡すクエリ名（既定 `page`） |
| `pageBase` | 整数 | `style=page` のときの開始番号（既定 `1`） |
| `pageSize` | 整数 | 1 ページあたりの取得件数。省略時は要求件数 |
| `maxResults` | 整数 | このエンジンで取得できる上限。既定 `30` |
| `offsetStep` | 整数 | `offsetParam` の増分。省略時は `pageSize` |

### 5.2 ページング非対応

`paging` を省略した場合、`maxResults` は 1 ページ分（要求件数）とみなし、「8 件目以降を見る」操作は「これ以上の結果はありません」と表示する。

---

## 6. エンジン固有の上限（`limits`）

| キー | 型 | 内容 |
|---|---|---|
| `maxResults` | 整数 | 累積取得件数の上限（既定 30）。`paging.maxResults` と併用時は小さい方 |
| `minIntervalMs` | 整数 | このエンジンへの最小リクエスト間隔（既定はネットワークプロファイルの値） |
| `maxPageSize` | 整数 | 1 回のリクエストで要求できる件数の上限（既定 10） |
| `requiresApiKey` | 真偽値 | `true` のとき認証情報が無ければ選択不可 |

---

## 7. 定義の配置と読み込み

### 7.1 配置場所と探索順

次の順に探索し、同一 `id` が複数ある場合は先に見つかったものを優先する。

1. `--engines-dir` で指定されたディレクトリ
2. 状態ディレクトリの `engines/`
3. 利用者設定ディレクトリの `engines/`（`~/.config/llmsearch/engines/`）
4. 同梱の既定エンジン（`engines/`）

### 7.2 複数定義の束ね（プロファイル）

同一エンジンに対して複数の定義（API 版・HTML 版など）を用意する場合、`id` を変えずに `variant` で区別する。`variant` は省略可能で、省略時は `default` とみなす。選択は `<id>` または `<id>@<variant>` で行う。

### 7.3 フォールバック

設定 `search.fallback` にエンジン ID の配列を指定すると、選択中エンジンが `E4001`（結果なし）または `E4003`（制限）を返した場合に限り、次のエンジンで再試行する。ネットワーク障害（`E2xxx`）では自動フォールバックしない（原因の切り分けを妨げるため）。フォールバックが発生した場合は `W4005` として記録し、どのエンジンで成功したかを表示する。

### 7.4 複数エンジンのマージ（任意機能）

設定 `search.merge` が `true` の場合、`search.engines` に列挙した複数エンジンの結果を交互に統合する。統合は「各エンジンの順位を正規化し、1 位から順に 1 件ずつ取り出すラウンドロビン」とし、重複は URL で除去する。マージ時は各結果に由来エンジン `engine` を付す。

## 8. 検証コマンド

### 8.1 `engines list`

利用可能なエンジン定義を 1 行 1 件で表示する。表示項目は `id`、`variant`、`kind`、`enabled`、`tags`、`requiresApiKey` と、認証情報の設定状況（設定済み／未設定）である。認証情報の値は表示しない。

### 8.2 `engines show <id[@variant]>`

定義の内容を、既定値で補完した解決済みの形で表示する。`--raw` 指定時は解決前の JSON をそのまま表示する。

### 8.3 `engines validate [<id>...]`

全件または指定分の定義を検証し、次を確認する。

1. `schemaVersion` の対応可否
2. 必須キーの存在と型
3. セレクタ・JSON パスの構文
4. `value_env` の参照先環境変数の有無
5. `paging` と `limits` の整合（`offsetStep` が 0 でない、`maxPageSize` が 1 以上）
6. `defaults` の値の妥当性

結果は `[ok]` / `[warn]` / `[fail]` で 1 行ずつ表示し、失敗が 1 件でもあれば終了コード `1` を返す。

### 8.4 `engines test <id[@variant]> --query <q>`

実際に 1 回だけ検索を行い、抽出結果の先頭 3 件と抽出できなかった件数を表示する。クォータを消費するため、実行前に消費量を示す。`--dry-run` 指定時はリクエストの組み立て結果（URL・ヘッダ・本文）のみ表示し、送信しない。ヘッダの認証情報は伏字化する。
