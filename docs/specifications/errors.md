# 仕様書: エラーと診断

本書はエラーコード体系、警告、メッセージの方針、`doctor` による自己診断の仕様を定義する。

---

## 1. コード体系

### 1.1 分類

エラーコードは `E` に続く 4 桁で表す。先頭 1 桁が分類、残り 3 桁が通し番号である。終了コードは分類に対応する。

| 分類 | 範囲 | 意味 | 終了コード |
|---|---|---|---|
| 入力 | `E1xxx` | 引数・入力・設定・エンジン定義の誤り | 1 |
| ネットワーク | `E2xxx` | 接続・取得・リダイレクトの失敗 | 2 |
| 変換 | `E3xxx` | 本文抽出・Markdown 変換の失敗 | 3 |
| エンジン | `E4xxx` | 検索エンジン・応答抽出の失敗 | 4 |
| 状態 | `E5xxx` | セッション・履歴・クォータ・状態の不整合 | 5 |

### 1.2 警告

警告は `W` に続く 4 桁で表し、終了コードには影響しない。`--quiet` でない場合は標準エラーへ出力する。JSON 出力時は操作内の警告を対象イベントの `warnings` 配列に含める（`--quiet` でも保持）。`--color --json` の `W1001` は独立した `warnings` イベントとして出力するが、`--quiet` では標準エラーとイベントの両方を抑制する。

## 2. エラー一覧

### 2.1 入力エラー（`E1xxx`）

| コード | 状況 | メッセージの方針 | 回復手段の提示 |
|---|---|---|---|
| `E1001` | 非端末での対話起動 | 対話モードは端末でのみ利用できる | サブコマンドの一覧を表示 |
| `E1002` | 不明なサブコマンド・引数 | 不明な引数 `<arg>` | `--help` の案内 |
| `E1003` | 設定・定義ファイルが読めない／壊れている／参照解決不能、またはネットワーク・フィルタ等の資源 ID が無い | パスと行・桁。資源 ID の場合は `network profile '<id>' was not found` / `filter set '<id>' was not found` | 資源 ID の場合は hint に利用可能な ID と `network list` / `filters list` を示す。その他は該当箇所の修正、`config init` |
| `E1004` | 設定・定義の値が範囲外・型不正・必須欠落 | キーのパス・指定値・許容範囲 | 原因に対応する許容値を提示する（例: `quota reset --scope` は `session` / `day` / `window` / `total` / `all`）。設定由来の場合は `engines validate` |
| `E1005` | 不正な選択入力 | 解釈できない指定 | 入力箇所に合う形式を示す。`read --section` は `S3` / `D1:S3` / `S0`、結果選択は `1,3` / `1-3` / `R1` |
| `E1006` | 対象識別子が現行セッションに無い | 識別子と、可能な場合は利用可能な識別子の一覧 | 結果・文書の参照は有効な ID を選ぶ。`read --section` は `outline` で節一覧を確認する |
| `E1007` | 検索語が空 | 検索語が空である | 検索語の入力を促す |
| `E1008` | テンプレート変数が未知 | 未知の変数名 | 使用可能な変数の一覧 |

### 2.2 ネットワークエラー（`E2xxx`）

| コード | 状況 | メッセージの方針 | 回復手段の提示 |
|---|---|---|---|
| `E2001` | 接続失敗（DNS・拒否） | ホスト名と理由 | 別の結果の選択、時間を置いた再実行 |
| `E2002` | タイムアウト | 経過時間と設定値 | タイムアウト値の変更 |
| `E2003` | HTTP エラー応答 | ステータスコード | 4xx は別 URL、5xx は再試行 |
| `E2004` | リダイレクト過多・ループ | 追従回数と最終 URL | 元 URL の確認 |
| `E2005` | 非対応スキーム・非 HTML | Content-Type とスキーム | 対応形式の提示 |
| `E2006` | robots.txt による拒否 | 該当ルール | 別 URL の選択 |
| `E2007` | 応答サイズ超過 | 上限値 | 上限設定の変更 |
| `E2008` | TLS 検証の失敗 | ホスト名と理由 | CA 設定の確認（`tls.caFile`） |

`E2007`（応答サイズ超過）は初期リリースでは発行しない。応答が上限を超えた場合は読み取りを打ち切り、警告 `W3003` を出して変換を続ける（`document-fetching` の仕様を参照）。将来、打ち切りを許さない用途が定まった時点で発行する。

### 2.3 変換エラー（`E3xxx`）

| コード | 状況 | メッセージの方針 | 回復手段の提示 |
|---|---|---|---|
| `E3001` | 本文が抽出できない | 抽出後の文字数 | 本文全体を対象にした再試行 |
| `E3002` | 非対応形式（PDF 等） | Content-Type | 別の結果の選択 |
| `E3003` | 文字コード判定の失敗 | 判定に用いた情報 | 文字化けの可能性の注記 |
| `E3004` | Markdown 変換の失敗 | 失敗した要素の種類 | 抽出方式の変更 |

### 2.4 エンジンエラー（`E4xxx`）

| コード | 状況 | メッセージの方針 | 回復手段の提示 |
|---|---|---|---|
| `E4001` | 結果が 0 件（抽出結果を含む） | 検索語とエンジン ID | 検索語の修正、別エンジン |
| `E4002` | エンジンが利用不能（無効・認証情報不足・定義不備） | 不足している項目 | 設定方法、`engines list` |
| `E4003` | レート制限・拒否（429・403 等） | 応答コードと待機時間 | 待機後の再実行、エンジン変更 |
| `E4004` | 応答の解析失敗（抽出ルール不一致） | 応答の先頭テキスト | `engines test` でのセレクタ修正 |
| `E4005` | エンジン定義の重複 ID | 重複した ID とパス | 定義の整理 |
| `E4006` | 抽出規則の適用結果が不正（相対 URL など） | 破棄した件数 | `absolutize` 変換の追加 |

### 2.5 状態エラー（`E5xxx`）

| コード | 状況 | メッセージの方針 | 回復手段の提示 |
|---|---|---|---|
| `E5001` | 明示したセッションが存在しない、または既存セッションが必要だが見つからない | 指定 ID、またはセッション不在の理由 | 既存 ID を選ぶか、`--session` なしで `search` を実行 |
| `E5002` | 状態ディレクトリに書き込めない | パスと理由 | 権限・容量の確認 |
| `E5003` | 同時更新の衝突 | 対象セッション | 再実行 |
| `E5004` | 履歴ファイルの破損 | 読み飛ばした行数 | `export` による退避と再作成 |
| `E5005` | クォータ超過 | 項目名・要求量・現在の消費量／上限・要求後の見込み量・リセット時刻 | 待機、ポリシー変更、`quota reset` |

## 4. メッセージの方針

### 4.1 構成

エラーメッセージは「何が起きたか」を 1 文で示し、続けて「なぜか」「どうすればよいか」を箇条書きで示す。原因が不明な場合は推測を断定しない。

### 4.2 言語

利用者向けのメッセージはすべて英語で表示する。エラーコード・警告コード・JSON のフィールド名も言語に依存しない。メッセージの言語を切り替える設定は存在しない（`ui.locale` は廃止した。§4.5）。

定型文（`message` / `hint`）、JSON の `message` / `hint`、標準エラーの文言、`doctor` や検証結果に埋め込む文言、対話メニュー、`--help`、進捗表示のいずれも英語とし、表示経路によって言語が混ざらないようにする。詳細文（`details`）は、生成時に得られた値をそのまま載せるため翻訳しない（外部から得た日本語の本文・URL・エンジン名などはそのまま現れる）。

エラーに個別の `hint`（その場の状況に合わせた回復手順）がある場合は、カタログの定型 `hint` より優先する。個別の `hint` も英語で用意する。

`search.language`（`configuration.md`）は検索エンジンへ送る言語であり、表示言語には影響しない。値を変えても CLI の表示は常に英語のままである。

### 4.3 出力先

エラーは標準エラーへ出力する（`--quiet` でもエラーは抑制しない）。警告は `--quiet` でない場合に標準エラーへ出力する。JSON モードでは、設定解決時とコマンド実行中に `Reporter` 経由で発行された警告を失わず、次のデータイベントが `warnings[]` を持つ場合はそこへ含め、持たない場合は直前に `warnings` イベントを出す。これらの構造化警告は `--quiet` でも維持する。エラーは `error` イベントに、失敗に至る過程で出た警告はその `warnings[]` に含める。`--color --json` の `W1001` は独立した `warnings` イベントにするが、`--quiet` ではこのイベントを出さない。JSON Lines 以外の進捗・診断文言は標準出力へ混ぜない。

### 4.4 秘匿情報

メッセージに API キー・Cookie・認証ヘッダを含めない。URL は秘匿パラメータを伏字化して表示する。

### 4.5 廃止した `ui.locale`

`ui.locale` 設定、`LLMSEARCH_UI_LOCALE` 環境変数、`Locale` の列挙は廃止した。メッセージは常に英語である。

- 旧 `settings.json` に `ui.locale` が残っている場合は、未知キーとして警告 `W1002` を出し、処理は継続する（値は書き戻し時に保持する）。警告の文言には、このキーが廃止され表示は常に英語であること、検索エンジンの言語には `search.language` を使うことを含める。
- 旧 `LLMSEARCH_UI_LOCALE` が設定されていても無視する（エラーにしない）。`config show` の解決結果にも現れない。
- `ui` 配下の未知キーは温存し、`W1002` の対象にする（`configuration.md` §6.2）。

## 5. `doctor` による自己診断

### 5.1 診断項目

`doctor` は次の項目を順に確認し、各項目を成功・警告・失敗で表示する。

1. アプリ版・ビルド時の Rust コンパイラ版・OS・アーキテクチャ
2. 状態ディレクトリの存在と書き込み可否
3. 選択中のネットワークプロファイルと検証結果・ポリシー警告
4. 有効なフィルタ規則数とクォータポリシーの検証結果
5. 全エンジン定義と認証環境変数（未設定の認証情報は警告）
6. クォータ使用量、既定エンジンへの到達性（1 回の GET。`--no-network` で省略可）
7. 履歴を読み込めるか、キャッシュが有効か
8. 現行セッションと既定エンジン
9. 失敗件数と該当するエラーコードの要約

状態ディレクトリの失敗は `E5002`、ネットワーク・クォータ・エンジン定義の検証失敗は `E1004` として示す。認証情報の不足と到達性の失敗は警告として示す。

### 5.2 結果の表示

各項目は 1 行で `[ok]` / `[warn]` / `[fail]` を先頭に付け、失敗項目には次の操作を提示する。`--json` 指定時は `diagnostics` イベントで診断結果の配列を出力する。

### 5.3 ネットワーク診断の制約

到達性の確認は既定エンジンの検索 URL に対する GET 1 回に限定し、検索クエリを送信せず、クォータも消費しない。`doctor --no-network` は到達性要求を送らず、`network.reachability` を `[warn] skipped (--no-network)` と表示する。
