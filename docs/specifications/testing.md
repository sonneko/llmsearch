# 仕様書: テストと品質基準

本書は、実装の正しさを判断するための受入基準、テスト層、品質ゲートを定義する。実装手段には依存しない。

---

## 1. 受入基準

### 1.1 対話フローの受入基準

1. 検索実行後、既定 7 件の結果が番号・タイトル・URL・スニペットの形式で表示される。
2. メニューは「終了 / 検索結果の選択 / 8 件目以降を見る / 検索ワードの修正」の 4 項目を、この順番と番号で表示する。
3. 「8 件目以降を見る」で 8〜14 件目が表示され、既に表示した結果の識別子が変化しない。
4. 結果を選択すると、各文書の h1〜h3 の見出しと節の文字数が表示され、本文は表示されない。
5. 節を選択すると、その節の本文のみが出力され、他の節の本文が混入しない。
6. 出力の文字数が予算を超える場合、行境界で切り詰められ、切り詰めた旨が表示される。
7. 検索ワードの修正後、新しい結果一覧が表示され、以前の結果は履歴から参照できる。
8. 履歴から過去の節を再出力でき、出力内容が見出し構成と一致する。

### 1.2 非対話・エージェント連携の受入基準

1. `--json` 指定時、標準出力の各行が単体で解析可能な JSON である。
2. 各コマンドは最後に `done` または `error` を 1 つだけ出力する。
3. エラー時に終了コードが分類に対応し、`error.code` がメッセージと一致する。
4. `search` → `outline` → `read` を別プロセスで実行しても、セッション識別子により状態が引き継がれる。
5. 標準出力にメニュー・進捗・警告が混入しない。

### 1.3 変換の受入基準

1. 見出し・段落・リスト・表・コードブロック・リンク・強調が Markdown として保持される。
2. 相対 URL が絶対 URL に変換される。
3. コードブロック内の行頭 `#` が見出しとして抽出されない。
4. 同一の HTML 入力に対して、変換結果がバイト単位で一致する（決定論性）。

### 1.4 安全性の受入基準

1. 外部コンテンツの出力には出所 URL と信頼境界のマーカーが付く。
2. 履歴・JSON 出力に API キー・Cookie・認証ヘッダが含まれない。
3. robots.txt が拒否する URL への取得を行わない。

## 2. テスト層

### 2.1 層構成

| 層 | 対象 | 目的 |
|---|---|---|
| 契約テスト | 仕様書の各章の記述 | 仕様の記述と実装の一致を検証する |
| 単体テスト | HTML→Markdown 変換、見出し抽出、節分割、予算配分、入力パーサ、URL 正規化 | 純粋なロジックの正しさ |
| 結合テスト | 検索→選択→取得→アウトライン→節出力の流れ | 層をまたぐ連携 |
| ネットワークモックテスト | プロバイダ応答、HTTP 応答、robots.txt | 外部依存を固定した再現性 |
| E2E テスト | 実際の端末での対話、実際の公開ページ取得 | 実環境での動作 |

### 2.2 外部依存の扱い

ネットワークを伴うテストは、記録済みの応答（フィクスチャ）を再生する方式を既定とし、実ネットワークへのアクセスは明示的なフラグ指定時のみ行う。フィクスチャは手作業で編集せず、取得スクリプトの出力をレビューして確定する。

### 2.3 決定論性の担保

変換・抽出・見出し識別子・URL 正規化について、同一入力から同一出力が得られることをテストで検証する。乱数や現在時刻に依存する値は、注入可能な時計・乱数源を経由させる。

## 3. 品質ゲート

### 3.1 コミット前

1. ドキュメント規則検査が通過する。
2. 静的解析とフォーマット検査が警告なしで通過する。
3. すべての単体テストと結合テストが通過する。

### 3.2 リリース前

1. E2E テストが通過する。
2. `doctor` が既定プロバイダで全項目成功する。
3. 出力サンプル（一覧・アウトライン・節本文・JSON イベント）が仕様の記載と一致する。
4. 履歴・セッションの容量管理が想定サイズで動作する。

### 3.3 カバレッジの方針

行カバレッジの数値目標は設けない。代わりに、仕様書の各節に対応するテストが 1 件以上存在することを必須とし、対応表を設計書側で管理する。

---

## 4. 回帰の扱い

### 4.1 期待出力の差分

変換結果や出力フォーマットの期待値に差分が生じた場合は、退行として扱う。仕様変更に伴う差分である場合は、仕様書の改訂承認を得たうえで期待値を更新する。

### 4.2 固有名詞・サンプルの固定

出力サンプルに用いる URL・タイトルは実在のページに依存させず、テスト用の固定データを用いる。
