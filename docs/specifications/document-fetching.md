# 仕様書: 文書取得と変換

本書は選択された検索結果から HTML を取得し、本文を抽出して Markdown へ変換するまでの仕様を定義する。

---

## 1. 取得

### 1.1 対象

取得対象は、検索結果として選択された URL、`outline` / `read` に URL として与えられたもの、履歴から再出力する際にキャッシュが失効している URL である。検索結果に含まれない URL への巡回は行わない。

### 1.2 プロトコルと制限

- 対応スキームは `http` と `https` のみとする。それ以外（`file:`, `ftp:`, `data:` 等）は拒否する（`E2005`）。
- リダイレクトは最大 5 回まで追従し、最終 URL を文書の正規 URL とする。ループは `E2004` として検出する。
- Content-Type が `text/html` または `application/xhtml+xml` であることを確認する。`application/pdf` および画像・バイナリは初期リリースでは非対応とし、`E3002` を返して理由を表示する。Content-Type が不明な場合は本文の先頭バイト列で HTML らしさを判定する。
- 応答本文の最大サイズは既定 5 MiB とする。超過した場合は打ち切って変換を続け、警告を出す。
- タイムアウトは接続 5 秒、全体 20 秒を既定とする。

### 1.3 文字コード

`Content-Type` の charset、HTML 内の `meta charset`、`@charset` の順に判定する。判定できない場合は UTF-8 とみなし、置換文字が生じた場合は警告を出す。

### 1.4 圧縮とキャッシュ制御

`gzip` / `deflate` を受理する。`Accept` ヘッダは HTML を優先する。`Cache-Control: no-store` を返した文書はキャッシュへ保存しない。

---

## 2. 本文抽出

### 2.1 目的

ナビゲーション、広告、フッタ、コメント欄などの定型ノイズを除去し、記事本文を主成分とする HTML 断片を得る。初期リリースでは Mozilla Readability 相当のアルゴリズムを既定とする。

### 2.2 手順

1. `script`, `style`, `noscript`, `iframe`, `svg`, `canvas`, `form`, `nav`, `aside`, `footer`, `header` のうち、本文推定で不要と判断された要素を除去する。
2. 候補要素のテキスト密度・段落数・リンク密度から本文領域を推定する。
3. 見出し・段落・リスト・表・引用・コードブロック・画像の参照を保持する。
4. 本文推定に失敗した場合は、`<body>` 全体を対象に変換し、警告 `W3001` を出す。

### 2.3 メタデータの取得

タイトル、サイト名、著者、公開日、言語、`og:title`、`canonical` を取得する。取得できない項目は空とし、代替値を創作しない。

### 2.4 JavaScript 依存ページ

本文抽出後の本文が既定 200 文字未満、かつ HTML 内に代表的なクライアントサイド描画の兆候（`<div id="root">` のみ、`__NEXT_DATA__` のみ、`noscript` 内の「JavaScript を有効にしてください」等）がある場合、描画不足の可能性を警告 `W3002` として表示する。初期リリースでは描画を行わない。

## 3. Markdown 変換

### 3.1 変換規則

| HTML | Markdown |
|---|---|
| `h1`〜`h6` | `#`〜`######` の ATX 見出し。レベルは保持する |
| `p` | 段落。空行で区切る |
| `strong`, `b` | `**` |
| `em`, `i` | `*` |
| `code`（インライン） | バッククォート。内容にバッククォートを含む場合は区切りを増やす |
| `pre` | フェンス付きコードブロック。言語クラスが分かれば info string に反映する |
| `ul`, `ol`, `li` | `-` および `1.`。入れ子は 2 スペースでインデントする |
| `blockquote` | `>` |
| `table` | パイプ記法のテーブル。セル内の `\|` はエスケープする |
| `hr` | `---` |
| `br` | 行末の 2 スペース改行 |

リンクは `a` 要素を「リンクテキスト（URL）」の形式で表し、相対 URL は文書の正規 URL を基準に絶対化する。画像は `img` 要素を代替テキストと URL の組で表し、代替テキストが空の場合も省略せずに出力する。

### 3.2 見出しの同一性

見出しテキストは、HTML のインライン要素を平坦化し、連続する空白を 1 つにまとめ、前後の空白を除去して生成する。見出しレベルは HTML の `h1`〜`h6` に対応させ、補正（例: h1 が存在しない場合に h2 を h1 へ格上げする）は行わない。

### 3.3 正規化

- 連続する空行は最大 1 行に圧縮する。
- 行末の空白を除去する（`br` 由来の 2 スペースは保持する）。
- リンクの URL は絶対 URL とし、`javascript:` および `data:` スキームはテキストのみ残す。
- HTML エンティティを復号する。
- 変換後の文字コードは UTF-8、改行は LF とする。

### 3.4 変換結果の保存

変換結果は Markdown 本文とメタデータ（取得日時、元 URL、最終 URL、タイトル、サイト名、文字数、見出し数、使用した変換方式、警告一覧）を合わせて保存する。

---

## 4. キャッシュ

### 4.1 保存単位

文書は URL ごとに 1 件保存する。同一 URL を別セッションで取得した場合、有効期限内であればキャッシュを再利用し、外部へのリクエストを行わない。

### 4.2 有効期限

既定 24 時間。`cache.ttl` で変更できる。`--refresh` 指定時、または `read` 時点で本文が保存されていない場合は再取得する。

### 4.3 無効化

「再取得する」指示があった場合、または前回の変換で `W3001` / `W3002` が出ている場合は、アウトライン表示時に「キャッシュが不完全な可能性」を注記し、再取得を選択できる。

### 4.4 保存しない場合

`no-store` を返した文書、`network.cache=false` の設定時、`--no-cache` 指定時はキャッシュへ保存しない。この場合も履歴には記録するが、本文は保存しない。
