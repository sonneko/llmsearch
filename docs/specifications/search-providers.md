# 仕様書: 検索プロバイダ

本書は検索段階の仕様（プロバイダ、結果の正規化、ページング、検索語の修正、レート制限）を定義する。

---

## 1. 対象プロバイダ

### 1.1 一覧

| プロバイダ | 認証 | ページング | 用途 |
|---|---|---|---|
| `duckduckgo` | 不要 | 対応（既定の上限 30 件程度） | 既定。API キーなしで動作する |
| `searxng` | 任意 | 対応（インスタンスに依存） | 自前・公開インスタンス。ENGINES を指定可能 |
| `brave` | API キー必須 | 対応（既定の上限 20 件程度） | 精度重視。キーは環境変数または設定で与える |

**決定**: 既定プロバイダは `duckduckgo` とし、`brave` はキーが設定されている場合のみ選択可能とする。理由は、API キーなしで起動でき、初期導入の障壁が最も低いためである。

### 1.2 プロバイダの選択順

1. コマンドラインの `--provider`
2. 環境変数 `LLMSEARCH_PROVIDER`
3. 設定ファイルの `search.provider`
4. 既定値 `duckduckgo`

上位が優先される。選択されたプロバイダが利用不能（キー未設定、接続不可）な場合は、`doctor` の推奨事項を添えたエラー（`E4002`）を返し、暗黙に別プロバイダへ切り替えない。

## 2. 検索結果の正規化

### 2.1 フィールド

検索プロバイダの差異を吸収し、各結果は次のフィールドに正規化する。

| フィールド | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | セッション内の識別子 `R1`, `R2`, … |
| `rank` | 必須 | プロバイダが返した順位（1 始まり） |
| `title` | 必須 | 結果のタイトル。HTML エンティティを復号し、空白を正規化する |
| `url` | 必須 | 正規化済みの URL（§2.2） |
| `snippet` | 任意 | 概要文。HTML タグを除去し、既定 120 文字で切り詰める |
| `site` | 任意 | 表示用のホスト名（`www.` を除く） |
| `published` | 任意 | プロバイダが公開日を返す場合のみ。`YYYY-MM-DD` 形式 |

### 2.2 URL の正規化

- 末尾の `?` および `#fragment` を保持するか否かは、同一 URL 判定のために必要最小限に留める。表示には元の URL を用いる。
- 追跡パラメータ（`utm_*`, `fbclid`, `gclid`, `yclid`, `msclkid`）を除去する。
- スキームは `https` を優先し、プロバイダが `http` を返した場合もそのまま表示する。
- プロバイダ固有のリダイレクト URL（例: 外部ドメインの転送エンドポイント）は、クエリに含まれる実 URL を抽出し、抽出できない場合はリダイレクトを解決する。

### 2.3 重複の除去

正規化後の URL が同一の結果は、初出の 1 件のみを残す。タイトルが完全一致し URL のホストとパスが同一のものも同一とみなす。

### 2.4 並び順

プロバイダの順位を維持する。重複除去後の順位は詰めず、元の順位を保持したまま識別子を連番で振る。

## 3. ページング

### 3.1 ページサイズ

既定は 1 ページ 7 件。`search.limit` および `--limit` で 1〜30 の範囲で変更できる。

### 3.2 次ページの取得

「8 件目以降を見る」操作は、同一クエリ・同一プロバイダで次のページを取得する。取得済みの結果は識別子を保持し、追加分には連番を継続して振る。ページ番号はセッション内で保持し、`next` コマンドでも同じ動作となる。

### 3.3 取得上限と終端

プロバイダの上限、または設定 `search.max_results`（既定 30）に達した場合は、追加取得を行わず「これ以上の結果はありません」と表示する。プロバイダが空ページを返した場合も同様に扱い、エラーとはしない。

### 3.4 失敗時の扱い

次ページ取得に失敗した場合、既に表示済みの一覧は保持したまま、エラー（`E4xxx`）を標準エラーへ表示し、メニューへ戻る。セッションの結果一覧を破棄しない。

---

## 4. 検索語の修正

### 4.1 挙動

「検索ワードを修正する」操作は、現在の検索語を初期値として提示し、編集後の文字列で新しい検索を実行する。直前の結果一覧はセッション内の別スロットとして保持し、履歴から参照できる。

### 4.2 検索語の履歴

セッション内の検索語は出現順に保持し、`!1`, `!2` の形式で再利用できる。履歴は表示用とし、空文字や空白のみの入力は受け付けない。

### 4.3 入力の正規化

前後の空白を除去し、連続する空白を 1 つにまとめる。全角空白は半角へ変換する。制御文字を除去する。最大長は 512 文字とし、超過分は切り捨てて警告する。

---

## 5. レート制限と礼儀

### 5.1 ホスト単位の制限

同一ホストへの連続リクエストは既定 1 秒以上の間隔を空ける。`search.min_interval_ms`（既定 1000）で変更できる。検索プロバイダへのリクエストも同一の制限対象とする。

### 5.2 同時実行

1 回の操作で同時に取得する文書は最大 2 件までとする。複数選択された場合は逐次処理し、進捗を標準エラーへ表示する。

### 5.3 robots.txt

本文取得の前に、対象ホストの robots.txt を取得して判定する。`User-agent: *` または `User-agent: llmsearch` に対する `Disallow` に該当するパスは取得しない。robots.txt が取得できない場合（404・タイムアウト）は取得を許可する。判定結果はセッション中キャッシュする。

### 5.4 User-Agent

既定値は `llmsearch/<version> (+<repository-url>)` とし、識別可能な文字列とする。`network.user_agent` で変更できるが、空文字は許可しない。
