# 仕様書: クォータとレート制限（JSON）

本書は「使いすぎない」ための上限を JSON で宣言する仕様を定義する。クォータは総量、レート制限は瞬間的な頻度を制御する。両者は独立して評価する。

---

## 1. 基本方針

### 1.1 2 種類の制御

| 種別 | 目的 | 単位 | 定義場所 |
|---|---|---|---|
| レート制限 | 短時間の連続アクセスを抑える | ホストあたりの最小間隔 | ネットワークプロファイルの `minIntervalMs` |
| クォータ | 総量（回数・件数・文字数）を抑える | セッション・日次・時間窓 | クォータポリシー（`quotas/<id>.json`） |

### 1.2 ポリシーの参照

設定 `quota` で ID を参照するか、インライン定義を記述する。`--quota <id>` と環境変数 `LLMSEARCH_QUOTA` で一時的に切り替えられる。

### 1.3 上限到達時の振る舞い

上限に達した場合、該当操作を実行せず、次の情報を返す。

1. 超過した項目名（例: `day.searches`）
2. 上限値と消費量
3. リセット時刻（次に窓が開く時刻）
4. 解除方法（設定変更・`quota reset`・待機）

暗黙に上限を超えること、自動で上限を緩めることは行わない。

---

## 2. クォータポリシーの構造

### 2.1 トップレベル

| キー | 必須 | 型 | 内容 |
|---|---|---|---|
| `schemaVersion` | 必須 | 整数 | スキーマ版（初期リリースは `2`） |
| `id` | 必須 | 文字列 | ポリシー ID |
| `description` | 任意 | 文字列 | 説明 |
| `enabled` | 任意 | 真偽値 | 既定 `true`。`false` のとき全項目を無制限とする |
| `session` | 任意 | オブジェクト | セッション単位の上限（§2.2） |
| `day` | 任意 | オブジェクト | 日次（端末のローカル日付）の上限（§2.3） |
| `window` | 任意 | 配列 | 任意の時間窓の上限（§2.4） |
| `total` | 任意 | オブジェクト | 累積の上限（§2.5） |
| `onExceed` | 任意 | 文字列 | `stop`（既定） / `warn` |

### 2.2 計測項目

各単位（`session` / `day` / `window` / `total`）で指定できる項目は次の 4 つである。省略した項目は無制限とする。

| キー | 型 | 内容 |
|---|---|---|
| `searches` | 整数 | 検索リクエストの回数（フォールバック・マージで送った回数も含む） |
| `fetches` | 整数 | 本文取得（HTML 取得）の回数。robots.txt とリダイレクトは数えない |
| `results` | 整数 | 取得した検索結果の件数（フィルタ前） |
| `chars` | 整数 | 出力した本文の文字数（`read` の合計） |

### 2.3 日次の区切り

`day` は端末のローカルタイムゾーンにおける 0 時で区切る。サーバー時刻や UTC では区切らない（利用者の体感と一致させるため）。タイムゾーンは `chrono::Local` を用い、設定で変更しない。

### 2.4 時間窓（`window`）

| キー | 必須 | 型 | 内容 |
|---|---|---|---|
| `minutes` | 必須 | 整数 | 窓の長さ（1〜10080） |
| `searches` ほか | 任意 | 整数 | 窓内の上限 |

窓は「スライディングウィンドウ」ではなく「固定窓」とし、最初の消費時刻から `minutes` 経過でリセットする。判定を単純にし、消費量の説明可能性を保つためである。

### 2.5 累積（`total`）

`total` は状態ディレクトリを作り直すまで減らない累積値である。`quota reset` で明示的に 0 にできる。

### 2.6 `onExceed`

- `stop`: 上限到達時に操作を中止する（既定）。
- `warn`: 上限到達後も操作を許可するが、毎回警告 `W5005` を表示し、履歴に `quotaExceeded: true` を記録する。上限の 2 倍に達した時点で `stop` に切り替わる（暴走の歯止め）。

## 3. 消費の単位と数え方

### 3.1 消費のタイミング

| 操作 | 消費する項目 | タイミング |
|---|---|---|
| `search` / `engines test` | `searches` +1、`results` に取得件数を加算 | 送信成功後 |
| `next` / `refine` | 同上 | 送信成功後 |
| `outline`（未キャッシュ） | `fetches` +1 | 取得成功後 |
| `outline`（キャッシュ済み） | 消費しない | — |
| `read` | `chars` に出力文字数を加算 | 出力後 |
| `history show` による再出力 | `chars` のみ加算（取得しない場合は `fetches` を消費しない） | 出力後 |

### 3.2 失敗時の扱い

- ネットワーク障害・タイムアウトで結果が得られなかった場合、`searches` / `fetches` は消費しない（再試行の余地を残すため）。
- ただし再試行（`retry`）の各試行は 1 回として数える。したがって `searches` は「送信した回数」、`results` は「得られた件数」である。
- `robots.txt` の取得、リダイレクトの追従、キャッシュからの再出力は消費しない。

### 3.3 消費の記録

消費は操作の成功直後に永続化する。プロセスが異常終了しても、成功済みの消費は失われない（書き込みは原子的に行う）。逆に、送信前に消費を先取りしない。

## 4. 状態と表示

### 4.1 カウンタの保持

カウンタは状態ディレクトリの `counters.json` に保持する。内容は「窓の開始時刻」「窓内の消費量」「日次・セッション・累積の消費量」である。セッション単位のカウンタはセッション状態と併せて保持する。

### 4.2 残量の表示

- すべての検索・取得・読み取りの出力に `quota` を含める。
- 対話モードでは、残量が 20% を切った項目がある場合に 1 行の注記を表示する。
- 上限到達時は、その場で理由とリセット時刻を表示する。

### 4.3 例

```text
quota: searches 12/50 (session), 340/500 (day, resets 2026-11-08T00:00+09:00), fetches 8/100
```

### 4.4 コマンド

| コマンド | 内容 |
|---|---|
| `quota show` | 全項目の上限・消費量・残量・リセット時刻を表示する |
| `quota reset [--scope session\|day\|window\|total\|all]` | 指定した範囲の消費量を 0 にする。`--yes` を要求する |
| `quota check --kind search\|fetch\|read --amount <n>` | 消費可能かを判定する（消費はしない）。スクリプトの事前確認用 |

---

## 5. 既定のポリシー

同梱の `default` ポリシーは次のとおり。利用者設定で上書きできる。

| 単位 | `searches` | `fetches` | `results` | `chars` |
|---|---|---|---|---|
| `session` | 50 | 100 | 500 | 200000 |
| `day` | 500 | 1000 | 5000 | 2000000 |
| `total` | 未設定 | 未設定 | 未設定 | 未設定 |

`window` は既定では設定しない（レート制限で頻度を抑えるため）。

---

## 6. 監査

### 6.1 履歴への記録

消費を伴う操作は履歴に記録し、消費量（`cost`）と残量（`remaining`）を含める。`quota reset` も履歴に記録する（誰がいつ何をリセットしたか）。

### 6.2 改変の検出

カウンタファイルが破損した場合、`W5001` を出して 0 から再開する。再開した旨と、直前の記録時刻を履歴に残す（上限の回避を意図した改変と、単なる破損を区別するための手がかり）。

### 6.3 上限の引き上げ

上限の引き上げは設定変更のみで行う。コマンドライン引数 `--quota` で別ポリシーを指定できるが、その場合も履歴に適用ポリシー ID を記録する。
