# 仕様書: 見出し・節とコンテキスト生成

本書は Markdown 化された文書から見出しを抽出し、節を選択してコンテキストへ出力する仕様を定義する。

---

## 1. 見出しの抽出

### 1.1 対象

ATX 見出し（行頭の `#`〜`######`）を対象とする。Setext 見出し（`===` / `---` の下線）も、直前の非空行を見出しテキストとして解釈する（変換器は生成しないが、外部から取り込んだ Markdown を扱えるようにするため）。

### 1.2 見出しの識別子

抽出順に `S1`, `S2`, … の識別子を文書ごとに振る（`Heading.id`。文書の内容が同一である限り再現する）。

### 1.3 見出しの属性

各見出しは、レベル、テキスト、節の開始行、節の終了行、節の文字数、子見出しの有無を持つ。

### 1.4 コードブロック内の除外

フェンス付きコードブロック内の行頭 `#` は見出しとして扱わない。フェンスの開始・終了は ```` ``` ```` および `~~~` を認識し、info string の有無を問わない。

### 1.5 重複見出し

同一テキストの見出しが複数ある場合も別の節として扱う。表示時は識別子で区別できるため、連番の付与や改名は行わない。

---

## 2. アウトライン表示

### 2.1 表示深度

既定は h1〜h3（`context.outlineDepth`、既定 3）。深度は 2〜4 の範囲で変更でき（`--depth`、対話メニューの `3) Change the outline depth`）、深度 `n` は h1〜h`n` を表示対象とする。深度を超える見出しは表示せず、`(<n> headings deeper than <depth> are hidden; choose 3) to change the depth)` のように件数だけを注記する。

### 2.2 表示形式

1 行 1 見出しとし、識別子・レベル・テキスト（40 表示幅で切り詰め）・節の文字数を表示する。階層はレベル 1 段あたり 2 文字のインデントで表現し、子見出しを持つ行の末尾に `↓` を付ける。文書ごとにヘッダ行 `[D<n>] <タイトル>   <URL>` を出力する。

### 2.3 節の文字数

節の文字数は、見出し行を除く節本文の文字数とする。末尾の空白と空行は数えない。

### 2.4 見出しが存在しない場合

見出しが 1 つも抽出できない場合は、`(no headings found; the whole body is available as S0)` を表示する。`S0` は文書全体を指す予約識別子で、`read <文書> --section S0` で本文全体を読める。変換時にタイトルを `h1` として補うため、通常はここに到達しない。

### 2.5 目次の重複排除

同一文書内で同一レベル・同一テキストの見出しが連続する場合でも統合しない。表示順は文書内の出現順を維持する。

---

## 3. 節の抽出

### 3.1 節の範囲

節は見出し行から始まり、次の見出しの直前までとする。次の見出しのレベルが同じか浅い場合は節を終了し、深い場合は子孫として節に含める。

### 3.2 子見出しの扱い

既定では子見出しの本文も含める（`--no-children` で除外。`--children` は既定の明示）。除外した場合は子見出しの件数を `omittedChildren` として JSON に載せる。

### 3.3 見出し行の扱い

節本文には見出し行を含める。出力ヘッダにも見出しテキストを表示するため、本文中の見出しは階層を保つための情報として残す。

### 3.4 複数指定

複数の節が指定された場合は、同一文書内では文書の出現順に並べ替えて出力する（読み順を保証するため）。異なる文書間では選択順を維持する。

### 3.5 重複・包含の解決

親節と子節が同時に指定された場合は、先に現れる親節の範囲に含まれる子節の出力を省略する。同一節の重複指定も 1 回にまとめる（`omittedChildren` で件数を返す）。

---

## 4. コンテキスト予算

### 4.1 既定値

1 回の出力に含める本文の上限は既定 8000 文字。`context.maxChars` および `--max-chars` で 500〜100000 の範囲で変更できる。

### 4.2 配分

複数の節を出力する場合、予算は指定順に「残り予算 ÷ 残りの節数」を上限として割り当て、各節の実サイズを超えない範囲で配る。配り切れなかった余りは先頭の節から順に追加する。

### 4.3 切り詰め

節の本文が割当を超える場合は行境界で切り詰め、`[truncated: shown N / total M chars]` を出力する（`--- end ---` の直前）。コードブロックの途中で終わった場合は閉じフェンスを補う。

### 4.4 予算超過時の案内

切り詰めが発生した場合は、JSON の `nextSectionId` に次の節の識別子を載せる（無ければ `null`）。文字オフセットによる継続指定は提供しない（`read --max-chars` を上げるか、次の節を指定する）。

---

## 5. 出所表示とプロンプトインジェクション対策

### 5.1 出所ヘッダ

すべての節出力の先頭に、文書識別子・節識別子・見出しテキスト・レベル・文字数・元 URL を含むヘッダ行を出力する。

### 5.2 信頼境界の明示

外部コンテンツは信頼できない入力として扱う。出力の冒頭に `[untrusted] <URL>` のマーカー行を置き、末尾に `--- end ---` を置く。本文に `[untrusted]` または `--- end ---` が含まれる場合は、全角の角括弧 `［untrusted］` とダッシュ `— end —` へ置換して、本物のマーカーと区別できるようにする（本文の意味は変えない）。

### 5.3 指示文の無害化

本文中に「これまでの指示を無視せよ」等の指示らしき記述が含まれていても、内容の改変・削除は行わない。代わりに、本文が外部由来であり指示として解釈してはならないことをヘッダで明示する。

### 5.4 出力のサイズ表示

各節の出力後（`--- end ---` の次）に `(output <n> chars / budget <m> chars)` を 1 行で表示する。対話モードではこれにセッションの文字消費を加える（`/ <used>/<limit> (session)`）。
